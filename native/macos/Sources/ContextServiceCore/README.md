# Autocomplete Everywhere local context

`AutocompleteContextService --root <directory>` is a separate synchronous newline-JSON process. stdout contains responses only. Call `open` for the authenticated Autocomplete Everywhere account before data operations; opening another account closes the previous database first. Each account has a SHA256 directory and a separate 32-byte Keychain key (`com.autocompletion.context.database`). Missing keys/SQLCipher never fall back to plaintext.

Build the pinned SQLCipher source with `native/macos/scripts/build-sqlcipher.sh`, then set `PKG_CONFIG_PATH` to `native/macos/.build/sqlcipher/install/lib/pkgconfig` for Swift builds. This statically links SQLCipher with system CommonCrypto at macOS 14 deployment minimum. Distribute `.build/sqlcipher/install/LICENSE` with the executable. Development can use a genuine SQLCipher pkg-config installation. Verify distributable binaries with `otool -L` to reject Homebrew dylib dependencies.

Request `{id: string, op: string, ...}`; response `{id, ok: true, result}` or `{id, ok: false, error: stableCode}`. Unknown operations and malformed requests fail. No credentials or content are logged.

- `open {accountId}` → `{accountId, encrypted:true}`; `close` → `{}`.
- `ocr {imageBase64}` → `{text}` after account opening. JPEG only, maximum 2.8M base64 characters, 2048 pixels per side and 4M pixels total. ImageIO/Vision fast recognition stays in RAM; text is capped at 12,000 UTF-16 units. Request lines are capped at 4,000,000 bytes.
- `pendingEmbeddings {limit?}` → `{evidence}` with at most 32 retained current records lacking a vector, saved references first; supports bounded background retry after restart.
- `put {evidence}` → `{changed:boolean}`. Evidence follows `packages/protocol/src/context.ts`; source account IDs are separate from the authenticated storage account.
- `revisions {sourceId,limit?,offset?}` → `{evidence,savedIds}`, including current and superseded audit revisions; never used by ordinary retrieval.
- `history {appId?,savedOnly?,limit?,offset?}` → `{evidence,savedIds}`; max page 200.
- `search {query?,appId?,documentId?,conversationId?}` → `{evidence,savedIds}`.
- `retrieve {query?,embedding?,appId?,documentId?,conversationId?}` → `{evidence,dependencies,revision,availability}`. Availability is `{text:"ready",semantic:"included"}` when a query embedding is supplied, otherwise semantic is `"not_prepared"`. Embeddings must contain 768 finite numbers.
- `validate {dependencies}` → boolean. Recheck before consuming generated results.
- `embed {evidenceId,revision,embedding}`, `save {evidenceId,saved}`, `delete {evidenceId}`, `deleteSource {sourceId}`, `purgeApp {appId}`, `clear`, `expire` → `{}`.

Original captures expire at the earlier explicit expiry or 30 days from capture. Repeated revisions do not overwrite or renew retained captures. Saved references have indefinite validity in transport, while their original stored timestamps remain unchanged. Revisions and dependency invalidation are transactional. Source changes archive the old revision and invalidated transitive dependents, excluding them from FTS/vector retrieval; a pinned source carries its saved state forward. Pin/unpin applies to that source and its archived revisions so unpinning does not leave hidden indefinite copies. Explicit source deletion, app purge, and deletion by evidence ID remove both live and archived dependent revisions. Clear removes unsaved history and archives, preserving saved references and live source dependencies they need. Encrypted 30-day source/revision tombstones prevent deleted/cleared revisions from reappearing through in-flight work or process restart; genuinely new revisions remain eligible. Expiration is swept on account opening and reads/validation; the desktop also requests periodic expiry while running. No contents are copied to plaintext temporary files. WAL pages are encrypted.

Retrieval combines exact source/id/URL matches, FTS5, cosine vector similarity, and recency using reciprocal rank fusion. Each channel returns at most 40 IDs; the fused top 40 supply at most 12 fragments and 8,000 UTF-8 text bytes (a conservative 8k-token bound). Vectors are decrypted once into a RAM-only normalized Float32 matrix; warm queries use Accelerate BLAS to rank them. Deleted vectors are zeroed and their slots reused. At 100k vectors, the matrix uses approximately 307 MB; memory scales with the retained embedded corpus and is not capped by silently dropping older recall. Cold index loading is measured separately from warm retrieval. `AUTOCOMPLETION_CONTEXT_BENCHMARK=1 swift test -c release ... --filter ContextServiceTests` enables the synthetic 100k vector corpus benchmark.

Verification on Apple M5 Pro: all 14 native tests pass, including the full-corpus benchmark, without reducing recall. Native tests also cover OCR JPEG validation/real Vision recognition, semantic availability, and pending-embedding recovery. Correctness covers encrypted files/WAL, wrong keys, retention, source/dependency invalidation, archive/tombstone replay prevention, saved references, account database isolation, filtered retrieval and cache deletion, and old strong phrase recall. Single-word full-corpus retrieval measured warm p95 35.21 ms and cold 670 ms. The final stronger benchmark alternates high-frequency single-word and multiword phrase queries: warm p95 **79.47 ms**, cold index+retrieval **707 ms**, passing the <100 ms warm-p95 gate without query-result caching or corpus subsets. Cold account/index loading remains separate from the warm target.

Memory scope: SQLCipher uses its [upstream default allocator](https://www.zetetic.net/sqlcipher/performance/). Cryptographic allocations remain locked and sanitized by SQLCipher; optional locking/wiping of every general SQLite allocation is not enabled. General SQLite allocations therefore share the ordinary process-memory lifecycle already used by Swift evidence and vector buffers. Database, WAL, and archive encryption, page authentication, SQLite/FTS secure deletion, and no-plaintext-persistence rules are unchanged. The optional all-allocation locking/wiping override was responsible for the previous 122–129 ms warm-p95 result.
